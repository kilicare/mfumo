### Transaction and cross-phase effect map

| Operation | Required source-of-truth effects | Acceptance invariant |
| --- | --- | --- |
| Create/update draft | Server-calculated line/invoice discounts, tax, totals, terms/dates; invoice number; audit/notification effects | No stock/cash/payment movement before issue/payment. Invalid product/customer/location/decimal/date/discount leaves no partial write. |
| Apply discount | DRAFT only; `sales.discount`; role-specific ceiling; recomputed tax/total/balance; audit | Direct endpoint and create/edit discount calculations agree; discount never makes taxable base or total invalid. |
| Issue/cancel | Open accounting period for inventory posting; credit-limit check; locked stock balances; outgoing inventory cost; SALE or SALE_REVERSAL movement; status metadata, audit, notification | Failure rolls back all stock/invoice/movement effects. Cancellation requires reason, no active payment and no unresolved return; cancellation does not erase history. |
| Record/reconcile/void payment | Tenant payment method; accounting-period check at record; stable idempotency; payment status; invoice balance/status; cash-flow/finance projections; audit | All invoice/customer/report summaries count active payment states consistently. Reconcile preserves paid value; void removes it once and recomputes invoice/customer balances. |
| Create/authorize/reject/receive return | Reserve sold quantity under invoice lock; authorization permission; terminal rejection; open period and one stock movement at receipt; outgoing unit cost; prorated discount/tax credit; invoice and customer balances | Draft/authorized reservation prevents over-return; rejected reservation releases quantity; receive once only; no inventory or credit effect before receive. Excess return credit stays on customer account. |
| Read/report | Tenant scope, recognized invoice/payment/return statuses, date-bound semantics, currency/rounding | Invoice detail, statement, dashboard summary and outstanding receivables reconcile to the same underlying records and statuses. |

## Logic flows to preserve

1. **Draft entry/edit:** permission-gated customer/product lookup plus `/sales/options` for locations/tax → validate 4-decimal quantities/prices and 2-decimal money → create/update only DRAFT → server derives terms/due date where omitted, computes line then invoice discount, then tax on the discounted base, and enforces customer credit for credit terms. The browser's estimate is never authoritative.
2. **Discount:** either include line/invoice discounts in draft create/edit or use dedicated percentage endpoint → require `sales.discount` and role limit (Owner/Admin 100%, Manager 25%, Salesperson 10%) → recalculate taxable amount, tax, total and balance → preserve audit trail. Test direct API permission and excessive aggregate discounts, not only UI hiding.
3. **Issue/cancel:** issue DRAFT only → `sales.approve` → open accounting period, active customer, credit limit, location stock lock and outgoing cost recheck in transaction → SALE movements + invoice issue metadata/audit/notification. Cancel with `sales.cancel` and reason; issued invoice reversal requires open period, zero active payment and no active return, posts SALE_REVERSAL and preserves invoice/audit history.
4. **Payment:** select active tenant payment method via `/payments/methods` → send positive cents amount to invoice-scoped route and stable idempotency key → backend checks issue state, open period, method and remaining balance → payment begins `RECORDED`; refetch invoice. Payments module reconciliation retains it as active; void removes it and recomputes invoice. Invoice response/customer summary/report calculations use the same active payment statuses.
5. **Return:** create only against issued invoice lines; aggregate prior DRAFT/AUTHORIZED/RECEIVED/COMPLETED reservations under invoice lock and reject over-return → draft or `authorizeNow` (requires approval permission) → DRAFT/AUTHORIZED can be rejected with reason and no effect → authorize → receive only in open accounting period, restore stock once at source outgoing cost, credit prorated invoice discount and tax, recompute invoice/customer balances. Excess credit remains on customer account and reduces future credit exposure; it does not trigger an automatic cash refund.
6. **List/filter/read/report:** invoice filters are `search`, `customerId`, `locationId`, `salespersonId`, `status`, inclusive `dateFrom/dateTo`, `sortBy/sortOrder`, `page/limit`; UI exposes all of them, dates validate and applying/resetting filters returns to page 1. Return filter is `search`, `salesInvoiceId`, `status`, `page/limit`. Read/report routes remain tenant-scoped and use recognized statuses consistently.
